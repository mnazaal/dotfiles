** server                                                             :emacs:
Start emacs blazingly fast. May have some issues with the =dashboard= package.

Every instance starts a server of its own rather than deferring to one already
running. =server-running-p= answers "is *a* server holding this socket", which is
true in a second Emacs, but AUCTeX tests =server-process= — "did *this* Emacs
start one" — and calls =server-start= unconditionally when it is nil (see
=TeX-source-correlate-start-server= under [[*tex][tex]]). With both instances named
=server= that call cannot succeed, and the second one warns "Unable to start the
Emacs server" every time a viewer is launched.

So the first instance keeps the default name, which is what a bare =emacsclient=
resolves to (the tmux =C-e= binding, anything using =EDITOR=), and later ones
take a PID suffix. Reaching those needs =emacsclient -s server-<pid>=; the
=%(emacs-server)= expander under [[*tex][tex]] fills that in for sioyek's inverse search so
a click lands in the Emacs that opened the document.

#+begin_src emacs-lisp
(use-package server
  :config
  (when (server-running-p)
    (setq server-name (format "server-%d" (emacs-pid))))
  (server-start))
#+end_src

** org                                                                  :org:
[[https://orgmode.org/worg/org-quotes.html][Some quotes]] regarding org-mode.

Current workflow:
- TODO items go to a single =inbox.org=.
- TODO items that may not be done (INACTIVE and CANCELLED) go to =backlog.org=.
- Follow the Eisenhower matrix:
  - TODO #A: Very important and very urgent. Tasks with deadlines/consequences.
  - TODO: Important and urgent. Tasks with unclear deadline but need to be done as soon as possible.
  - TODO #C or WAITING: Not that important or urgent, or your task depends on some input you are waiting for.
  - DELEGATED: Not important but urgent, and main responsibility of the task is handed to someone else.
  - INACTIVE or CANCELLED: Not important and not urgent.

- =C-c C-s=   : Schedule a headline entry.
- =C-c C-d=   : Set a deadline to a headline entry.
- =C-c C-t=   : Change TODO state.

** org-fc                                         :personal_management:notes:
Spaced repetition over headings tagged =:fc:= anywhere under =org-directory=.

=C-c v= opens the transient: =r= reviews, =d= is the dashboard, =i= followed by
a type initializes the heading at point as a card. Write cards in the compact
shape — heading is the front, body is the back, no =Back= subheading — which is
also the shape an Anki export expects.

Chosen over =org-srs= because review history stays OUT of the notes: the
heading keeps one small =:REVIEW_DATA:= table updated in place, and the
append-only log goes to a TSV under =user-emacs-directory=. It also has more
card types (text input, vocab, four cloze flavours). The trade is scheduling:
=sm2-v2= here is pure elisp and works immediately, whereas its FSRS algorithm
shells out to =python/algo_fsrs6.py=, which imports the =py_fsrs= git
submodule that =package-vc= does NOT clone. To switch to FSRS later, fetch the
submodule in the package checkout first.

Indexing shells out to =gawk= and =find=, which is why it stays fast over a
large =~/org=.

#+begin_src emacs-lisp
(use-package org-fc
  :vc (:url "https://github.com/l3kn/org-fc" :branch "main")
  :defer t
  :custom
  (org-fc-directories (list org-directory))
  (org-fc-algorithm 'sm2-v2)
  :config
  (require 'org-fc-transient)
  :bind
  ("C-c v" . org-fc-transient))
#+end_src

** magit                                                    :version_control:
Git interface.

The =magit= keybindings override some other Emacs keybindings for =goto= style actions.

- Fixup: If some changes were forgotten in the last commit, stage them, then use =c c F= (=F= for instant fixup). This would put the forgotten changes to the last commit.
- Merge conflicts: If there are merge conflicts, use =e= to get a better view, then press =A= or =B= depending on changes you wish to keep.
- Spinoff branches: If there are many local changes that are meant to be in a new branch, use =b s= in the magit buffer (=s= for spinoff) to put them in a new 'spinoff' branch.
- Stash/Pop: In the magit buffer, use =z z= to stash current changes, =z p= to pop them which will show them as unstaged changes in the magit buffer.

- Sometimes you need to apply your changes on top of some changes in a remote branch. One approach is to merge the =main= to your feature branch, however this creates an extra commit whose message is not that helpful. The other option is to do a =rebase=. This takes new commits from the branch you are pulling from, and then reapplies your own commits on top of the commits from the remote branch. This involves changing the history (so be careful to only use it with your own branches). To do the rebasing, first press =P=, then press =r= to turn on rebasing. Now, choosing the remote repository will do a rebase instead of a merge - it will show any conflicts if they exist. If at this point you want to undo everything, press =r a= (=a= for =abort=), or if everything is fine, finish the rebase with =r r=. After this, you can force push to the remote branch (by turning on =- f= after going to the Push menu after pressing =P=).
- To add files to =.gitignore=, go to the file you want to ignore in the =magit= buffer, and press =i= to show the =git ignore= menu, then press =t= for the simplest option to add the file to =.gitignore=.
- Interactive rebasing:
  - Good idea to backup your branch to a new branch, via =b n= (=n= for =new branch=) - this is because editing the history may delete some changes is rebasing goes wrong.
  - Suppose you want to edit a commit message (=reword=). Use =r i= to go to the magit interactive rebase buffer, then press the key word =reword= and change the commit message.
  - Reordering commits: In the interactive =magit= buffer, use =M-j,M-k= to move the commits up and down as needed.
  - If reordering commits introduces a conflict, first fix the conflicts, then *do not commit the new changes via* =c c=, instead use =r r=.
  - If the update needs changing the commit message, do a =squash=.
  - =d= to delete commits (in the rebase menu of course).
- Git worktrees:
  - Use case - you checked out a branch, and need to move onto something else. Normally, you would commit everything you have or stash your changes. In the meantime you need to checkout other branches etc. Worktrees allow of multiple commits to be checked out at the same time.
  - To start, use =git clone --bare xxxx=. Then checkout a worktree via =git worktree add foo=, =git worktree add bar= etc. This means you have separate checkouts in their own state. To remove them, use =git worktree remove foo=.

** tex                                                        :writing:latex:
AUCTeX. The workflow is: edit the source in terminal Emacs, view the compiled
PDF in a sioyek window tiled beside it, and recompile with =latexmk=. sioyek
polls the open PDF's mtime every 200ms and reloads once the file is stable, so
the view stays live without anything driving it from Emacs.

Commands worth remembering:
- =C-c C-c= run the default command (=LaTeXMk=), =C-c C-a= run every command needed.
- =C-c C-v= forward search: jump the viewer to the position of point.
- =C-c C-l= show the compilation log, =C-c `= step through errors.
- =C-c k= toggle continuous compile-on-save (see [[*auctex-cont-latexmk][auctex-cont-latexmk]]).
Note =preview-latex= (=C-c C-p C-d=) is not usable here: it renders images and so
needs a graphical frame.
- In sioyek, a mouse click jumps back to the corresponding source line (its
  =--inverse-search= calls =emacsclient -s=, so this instance's [[*server][server]] must be
  running).

More AUCTeX shortcuts are listed [[https://tex.stackexchange.com/questions/20843/useful-shortcuts-or-key-bindings-or-predefined-commands-for-emacsauctex/21026#21026][here]].

Notes on the settings:
- =LaTeXMk= is a built-in entry of AUCTeX's =TeX-command-list=; its
  =%(latexmk-out)= expander reads =TeX-engine=, which is left at its default
  (pdfTeX), so it expands to plain =-pdf= and latexmk uses its own =$pdflatex=.
  latexmk drives the pdflatex/biber/pdflatex chain itself, so no separate
  =auctex-latexmk= package is needed.
- The engine is pdflatex, not xelatex. Nothing here needs xetex — the Org
  exporter emits =inputenc= + =[T1]{fontenc}= and no =fontspec= — and measured
  on a representative preamble pdflatex is ~25% faster (1007ms vs 1334ms).
  This *requires* the =cm-super= package (=tlmgr install cm-super=): without it
  =[T1]{fontenc}= has no Type1 fonts, pdflatex silently falls back to generating
  bitmap fonts, and it becomes the slower engine instead of the faster one.
- =TeX-parse-self= makes AUCTeX read the document's own preamble, so completion
  and folding know about macros and environments defined in it or by its
  packages. =TeX-auto-save= caches that parse between sessions.
- =TeX-source-correlate-mode= is what passes =--synctex=1= through to the
  engine; without it neither forward nor backward search works.
- =%(emacs-server)= is a custom entry in =TeX-expand-list=; it expands to this
  instance's =server-name=, so the =--inverse-search= command sioyek stores
  points at the socket of the Emacs that opened the document rather than at
  whichever one happens to own the default =server= name. See [[*server][server]] for why
  each instance gets its own.
- No window flag is passed, and that is deliberate — it is what gives one
  sioyek window per manuscript. sioyek first looks for a window already
  displaying this PDF and reuses it, so repeated =C-c C-v= on one paper updates
  its window in place; failing that it honours =should_launch_new_window 1= from
  =prefs_user.config= and opens a new one. The two flags that look applicable
  are both wrong here:
  - =--reuse-window= exists to *override* =should_launch_new_window=. It forced
    every document into the first window, so two papers open at once fought over
    one view — and since =inverse_search_command= is stored per window, whichever
    Emacs ran =C-c C-v= last also captured every inverse-search click.
  - =--new-window= creates a window unconditionally, contrary to its =--help=
    text, which claims it reuses an existing window showing the same file. Each
    =C-c C-v= on the same paper would open another window.
- sioyek needs to be new enough: commit =5a262027= (2026-07-22) introduced a
  regression that segfaulted it whenever an open PDF was rewritten — exactly the
  live-reload case — fixed upstream by =fe698ba=. Build it through
  =pkgit -b sioyek,update=, never =./build_linux.sh= directly: the recipe pins
  the Qt 6.8 qmake, and the script's fallback silently picks the system Qt 5,
  which fails to compile.
- =flymake-mode= runs AUCTeX's own =LaTeX-flymake= backend, which shells out to
  =chktex= for the typographic errors latexmk never reports: a missing =~=
  before a reference, =...= instead of =\ldots=, wrong quote characters. Pass
  extra flags through =LaTeX-flymake-chktex-options=. =chktex= is a separate TeX
  Live package (=tlmgr install chktex=) and the backend is silent without it.
- The =eglot-managed-mode-hook= entry exists because [[*eglot][eglot]] *replaces*
  =flymake-diagnostic-functions= with its own single backend when it starts
  managing a buffer, which silently drops chktex the moment =harper-ls=
  attaches. Re-adding =LaTeX-flymake= buffer-locally afterwards lets both report
  into the same Flymake session. The alternative — putting =flymake= in
  =eglot-stay-out-of= — is global, so it would also disable eglot's Flymake
  handling for Python and shell buffers.

#+begin_src emacs-lisp
(use-package tex
  :ensure auctex
  :custom
  (TeX-save-query nil) ;; No need for the save command before compilation is completed
  (TeX-parse-self t)
  (TeX-auto-save t)
  (TeX-command-default "LaTeXMk")
  (TeX-source-correlate-start-server t) ;; Don't ask before starting the Emacs server
  (TeX-electric-math '("$" . "$"))
  (LaTeX-electric-left-right-brace t)
  (TeX-view-program-selection '((output-pdf "Sioyek")))
  (TeX-expand-list '(("%(emacs-server)" (lambda () server-name))))
  (TeX-view-program-list
   '(("Sioyek"
      ("sioyek %o"
       (mode-io-correlate
        " --forward-search-file \"%b\" --forward-search-line %n --inverse-search \"emacsclient -s %(emacs-server) +%2 %1\""))
      "sioyek")))
  :hook

  (LaTeX-mode . TeX-fold-mode)
  (LaTeX-mode . flymake-mode)
  :config

    (when (derived-mode-p 'LaTeX-mode)
      (add-hook 'flymake-diagnostic-functions #'LaTeX-flymake nil t)))
  (add-hook 'eglot-managed-mode-hook #'tex-setup-chktex-flymake))
#+end_src

For a continuously rebuilding PDF, run =latexmk -pvc= on the file in a terminal;
sioyek picks up each rebuild on its own. [[*auctex-cont-latexmk][auctex-cont-latexmk]] does the same from
inside Emacs and additionally reports errors through Flymake.

*** Per-paper =.latexmkrc=
Every paper repository gets its own =.latexmkrc=, committed alongside the
source. It is what makes Make, this AUCTeX setup, and a coauthor's checkout all
build the same way; without it each entry point carries its own flags and they
drift. Deliberately *not* installed as a global =~/.latexmkrc=: a coauthor who
clones the repo does not get the home directory with it.

#+begin_example
$pdf_mode      = 1;        # pdflatex, matching the engine choice above
$bibtex_use    = 2;        # always regenerate the .bbl; it is committed, not preserved
$aux_dir       = 'build';
$emulate_aux   = 1;        # TeX Live has no real -aux-directory
@default_files = ('main.tex');
$pdflatex      = 'pdflatex %O -synctex=1 -file-line-error -halt-on-error -interaction=nonstopmode %S';
#+end_example

- =$bibtex_use= controls both whether bibtex runs *and* whether cleanup deletes
  the =.bbl=. From latexmk's own source: =0= and =1= never delete it, =1.5=
  deletes it *if the bib files exist* — which they always do, so =1.5= is not the
  protection its name suggests — and =2= always deletes it. This template picks
  =2= and commits the =.bbl= instead: a stale bibliography that survives a clean
  is far more expensive to debug than a regenerated one, and arXiv (which does
  not run bibtex) gets its copy from version control rather than from whatever
  happens to be on disk.
- =$out_dir= is left unset, so the PDF stays at the repository root while the
  aux clutter goes to =build/=. That puts the =.bbl= in =build/= too, and git
  cannot re-include a file whose parent directory is excluded — so the
  =.gitignore= needs =build/*= followed by =!build/main.bbl=, *not* =build/=.
  Check it with =git check-ignore -v build/main.bbl=, which should report no
  match while =build/main.aux= stays ignored.
- Because the =.bbl= is tracked and =$bibtex_use= is =2=, =latexmk -C= deletes a
  file git knows about; =git status= shows the deletion until the next build
  restores it. That is the accepted cost of keeping "clean" honest.
- Overleaf runs its own compile and its handling of =$aux_dir= is unverified; if
  a web build breaks after a push, drop the two aux lines and keep the rest.
- =-shell-escape= is deliberately absent: arXiv will not run it, so a document
  that needs it cannot be submitted as source.

Built-in cross-referencing for LaTeX: label and reference completion that reads
the actual labels in the document, plus a jumpable table of contents.

- =C-c (= insert a label, =C-c )= insert a reference to an existing label.
- =C-c == table of contents for the whole document.
- =C-c [= insert a citation (reads =bib-file=; [[*citar][citar]] remains the richer
  interface, bound to =C-c b= in Org and =C-c r= for opening entries).

#+begin_src emacs-lisp
(use-package reftex
  :ensure nil
  :hook
  (LaTeX-mode . turn-on-reftex)
  :custom
  (reftex-plug-into-AUCTeX t)
  (reftex-toc-split-windows-fraction 0.3)
  (reftex-default-bibliography (list bib-file)))
#+end_src

** auctex-cont-latexmk                                        :writing:latex:
Compile-on-save, from GNU ELPA rather than hand-rolled. =latexmk -pvc= runs in
the background and rebuilds on every save, so there is no compile keystroke and
no minibuffer command prompt; Evince picks up each rebuild on its own. Unlike
running =latexmk -pvc= in a terminal, errors come back through Flymake, so the
existing =]d= / =[d= bindings (see [[*evil-collection][evil-collection]]) navigate LaTeX errors too.

=M-x auctex-cont-latexmk-toggle= (=C-c k=) turns it on per buffer.

Sharp bits:
- =auctex-cont-latexmk-command= is the *whole* command definition and does not
  read =TeX-engine=, so it is restated below. Keep the =-synctex=1= and
  =-file-line-error= flags in the =-e= payload: SyncTeX and Flymake's error
  parsing respectively depend on them.
- Diagnostics refresh only once latexmk reaches its "watching for changes" state
  *and* the buffer has no unsaved changes, so they lag a few seconds behind a
  save rather than updating as you type.
- Raw compiler output goes to a buffer named =*pvc-<filename>*=.
- Avoid parentheses in file names; AUCTeX's error parser mishandles them.

#+begin_src emacs-lisp
(use-package auctex-cont-latexmk
  :after latex
  :custom
  (auctex-cont-latexmk-command
   '("latexmk -pvc -pdf -view=none -e "
     ("$pdflatex=q/pdflatex %O -synctex=1 -file-line-error -interaction=nonstopmode %S/; $sleep_time=0.3;")))
  :bind
  (:map LaTeX-mode-map
        ("C-c k" . auctex-cont-latexmk-toggle)))
#+end_src
