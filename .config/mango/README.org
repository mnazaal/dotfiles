Mango configuration for the laptop Wayland session.

* Overview

This directory keeps Mango configuration split by concern.

- =config.conf= loads the other files and holds general Mango settings
- =env.conf= defines Mango/session environment variables
- =monitors.conf= defines monitor layout
- =appearance.conf= defines gaps, borders, colors, and visual behavior
- =input.conf= defines keyboard, pointer, and touchpad behavior
- =bindings.conf= defines key and mouse bindings
- =rules.conf= defines application/window rules
- =startup.conf= starts session services once Mango is running

* Startup graph

Mango is launched through the wrapper:

#+begin_src bash
~/.local/scripts/start-mango
#+end_src

The wrapper owns session-level environment setup. Do not duplicate those exports in zsh startup unless they are needed outside Mango.

Once Mango starts, =startup.conf= launches:

- =waybar= for the panel
- =dunst= for notifications
- =swayidle= with =~/.config/swayidle/config= for idle handling
- =swaybg= with =~/Pictures/wallpapers/wallpaper.png= for wallpaper

Screenshot bindings call =~/.local/scripts/screenshot=. Captures are saved to
=~/Pictures/screenshots= and failures are logged to
=~/.local/state/mango/screenshot.log=. If =notify-send= is installed, the
helper also sends Dunst/libnotify notifications for success, cancellation, and
known setup failures. Successful screenshot notifications pass the captured PNG
as the notification icon so Dunst can show a thumbnail when image previews are
enabled.

* Dependencies

Laptop setup expects these commands to exist, usually from source/manual builds or system packages:

- =mango=
- =waybar=
- =dunst=
- =swayidle=
- =swaybg=
- =grim=
- =slurp=
- =wl-copy= from =wl-clipboard=
- =brightnessctl=
- =wpctl= or compatible WirePlumber/PipeWire tools

* Workflow

Tags 1-5 are treated like simple workspaces. Keybindings live in =bindings.conf= and follow the comments there.

Common checks:

#+begin_src bash
command -v mango waybar dunst swayidle swaybg
~/.local/scripts/start-mango
#+end_src

If startup services do not appear, check =startup.conf= paths first. Most commands are expected under =~/.local/bin= in this setup.
