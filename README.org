Basic dotfiles.

* Deployment

Canonical deployment from repository root - creates symlinks in relevant directories
and, in the real login home, installs =~/.local/cron= as the *entire* live
crontab. Back up or merge existing personal cron jobs before the first run:
#+begin_src bash
make link
#+end_src

Run the isolated repository behavior tests with:
#+begin_src bash
make test
#+end_src

Run the full repository checks (tests, drift checks, doctor, linters) with:
#+begin_src bash
make check
#+end_src

=make check= requires ShellCheck, shfmt and PyYAML; missing tools or formatting
drift fail the full check rather than being skipped. The isolated =make test=
remains available without those lint dependencies. =make check= expects the
managed links created by =make link=. It warns when
the intentionally untracked =~/org/agenda= is absent; require it explicitly
with =dotfiles-doctor --strict=.

Remove only links owned by this repository with:
#+begin_src bash
make clean
#+end_src

A successful cleanup is silent. It does not remove unrelated symlinks or
tracked source files. Cleanup refuses while tracked cron jobs are live: first
run =make cron-unlink= in the real login home. That target removes only the
tracked jobs and preserves unrelated jobs and comments. It refuses if some
tracked jobs have drifted. It does not save the live crontab under the
agent-visible =~/.cache=: unrelated jobs may contain credentials. Arrange a
private backup outside the agent sandbox if you need one. =make clean= does
not alter the crontab.
The sync job in =~/.local/cron= restores the tracked schedule every 15 minutes;
edit the tracked file, not =crontab -e=, while the deployment is active.

Processes that start (or run) during =make clean= / =make link= capture the
half-deployed state and do not heal afterwards — relaunch them:
- agent sessions: directories that hold only stow links (=~/.agents=,
  =~/.claude/hooks=, …) are pruned and recreated with new inodes, so a sandbox
  launched earlier keeps the orphaned old directory bound and sees it empty —
  symptoms are "guardrail hook unavailable" permission asks and a system prompt
  missing the AGENTS.md include;
- shells: a zsh spawned in the gap misses =$ZDOTDIR/.zshrc= and keeps the stock
  prompt for its lifetime (=ZDOTDIR= itself survives via the inherited
  environment) — =exec zsh= restores it.

* Shell plugin setup

First-time zsh plugin installation is an explicit operation, not a shell
startup side effect. After linking, open zsh and run =zplugin-install= once;
use =zplugin-update= deliberately when updating plugins. An offline shell
starts without missing plugins rather than attempting to clone them.

* Sharp bits

If SSH from Kitty prints =missing or unsuitable terminal: xterm-kitty=, the remote host lacks Kitty terminfo.
Best local-machine fix: use Kitty's SSH kitten, which copies the needed terminfo before login:
#+begin_src bash
kitty +kitten ssh host
#+end_src

Fallback for one login:
#+begin_src bash
TERM=xterm-256color ssh host
#+end_src

or add this for that host in =~/.ssh/config=:
#+begin_src sshconfig
Host host
    SetEnv TERM=xterm-256color
#+end_src

Manual fix: copy terminfo with =infocmp= and install it on the server with =tic=.

* Notes on helper scripts

- source packages: =pkgit= builds everything under =~/.local= from the recipes
  in =.config/pkgit/= (see its README). =pkgit -i <pkg>= installs, =pkgit -b
  <pkg>,update= updates in place. Never =pkgit -u= or =-f=: both delete a
  package's source tree from under themselves
- no agent takes a prefix. =claude= and =claude-agent-acp= sandbox their Bash
  subprocesses through their own settings.json. =pi= and =pi-acp= use
  =.local/scripts/pi= to resolve the MCP key and launch the host process, while
  Pi's =shellPath= sends model Bash and user =!=/=!!= commands through
  =.local/scripts/pi-bash= and the shared =agent= sandbox profile. See
  =.config/sandbox/README.md=
- =.local/scripts/notmuch-cron= and =.local/scripts/rss2email-cron= depend on =pass=
- =.local/scripts/cal-sync-cron= depends on encrypted ICS URL files in password store
- =.local/scripts/onedrive-cron= depends on the =onedrive= client (abraunegg,
  from the OpenSuSE Build Service repository — not Ubuntu's package) having been
  authorised once interactively with a bare =onedrive=. It refuses =--resync=,
  and reports the client's mandatory-resync exit status rather than looping on it
- =.local/scripts/shell-share= depends on =ttyd=, =cloudflared=, and =tmux=
